> var:
 	- Hoisting with initialization.
 	- function scope.
 	- can be redeclared.
> let:
 	- Hoisting without initialization on Temporal Dead Zone (TDZ).
 	- block scope.
 	- can be reassign.
> const:
 	- Hoisting without initialization on Temporal Dead Zone (TDZ).
 	- block scope.
 	- must be initialized when declaration.
 	- cannot be reassign.

- Hoisting: variables take place in the memory before executing in the code.
- TDZ: space from the scope beginning until the declaration line, in this space cannot use the variable before initialization.
- const is immutable as reference but it can change the content or value of this reference.
- we use const more to prevent the reassign.

- Nodejs is single thread act as multi thread (non blocking) because of the Event loop.
- pros: web api handle any async task so it won not block the thread.
- cons: any intensive task in call stack (sync) like huge loop will block the thread until finish (block thread).
- solution: we can convert any sync request to async one, or we can use (worker thread) to make separate thread on the CPU for intensive tasks.

> EventLoop:
1 - JS engine execute sync tasks in call stack.
2 - JS engine send async tasks to Web API (Browser) or Libuv in (Nodejs) which is C++ library manages the Eventloop and implements async I/O.
3 - Libuv send I/O or heavy CPU operations to thread pool.
4 - Once an async operation completes, Libuv send its callback into the callback queue (micro and macro) queue.
5 - Eventloop pulls tasks from queues and pushes them into Call Stack with the execution periority, then JS engine execute it.

- promises.then(), async/await in Microtask queue.
- setImmediate, timers, I/O, fs, events tasks in Macrotask queue.
- Microtask has priority than Macrotask.
- process.nextTick has priority than micro queue tasks.

> Thread Pool:
- a set of threads in the background used to perform I/O or CPU-heavy operations like hashing, encryption, zip.
- Not all async operations use thread pool.
- they are 4 threads by default, process.env.UV_THREADPOOL_SIZE = 8;
- async fs.readFile(): libuv send the fun to thread pool to read the file, then go to the macro queue to execute the callback.

> process.nextTick use callback method to be executed after sync code and before any promise. 

> Note: The Promise constructor runs synchronously, but .then() callbacks run asynchronously as microtasks.

- Callback: function parameter inside another function, it is the first way for async in JS.
- Promise:
 	- solve Callback Hell.
 	- object represent task will happen in future.
 	- it may be pending, fulfilled, rejected.
 	- it handle errors using .catch()
 	- resolve() to clarify that promise executed successfully.
 	- promise without .then() execute sync.
 	- .then() make the promise async task in microtask.
 	- .then() return promise, register promise resolve callback.
 	- promise.all(): execute more then promise in parallel way, if one failed, all 				failed.
 	- promise.race(): return the first fast promise either success or fail.
 	- promise.any(): return the first successful promise.
- async await: syntax sugar for promise, handle errors using try and catch.

> fs:
- load the entire data in memory one time.
- fs.readFileSync(): block main thread.
- fs.readFile(): the async way, thread pool, macro queue.

> Streams:
- proccess large data chunk by chunk instead of loading it entirely into memory, improving performance and memory efficiency.

- streams types:
1. Readable Stream: read data.
2. Writable Stream: write data.
3. Duplex Stream: read and write.
4. Transform Stream: read data, transform (like encryption, zip), write.

- pipe(): connect streams, better performance.
fs.createReadStream('file.txt').pipe(fs.createWriteStream('copy.txt'));

- Backpressure: occurs when a writable stream cannot handle incoming data fast enough, so Node temporarily pauses the readable stream to prevent memory overflow.
- pipe() apply the Backpressure internal.

> Buffer: 
- node cannot access memory direct, it use buffer to deal with binary data in memory (files, streams, networking, encryption).

> Node process (app) use one core in CPU.

> Cluster:
	- allow make more than node process (instances of the same app) on other cors on the 	same server, each instance called (worker process) and each one has its own memory 	and eventloop.
	- pros: suitable for scaling server requests, OS distribute requests between 	instances.
	- cons: each worker has its own memory so its hard to share data, so we need Redis 	caching.
	- cluster consume more memory (RAM) and the communication between workers is 	slower.

> Worker Thread:
	- make another thread in the same process for heavy CPU tasks.
	- threads share the same memory, so consume less memory. 

> Why there are worker threads although Node is single thread?
- as the single thread is related to behaviour of JS itself, but Node allow make multible threads in the background.

> Load Balancer:
	- distribute requests between servers.
	- used in horizontal scaling.

- Vertical Scaling: increase RAM (Cluster).
- Horizontal Scaling: deploy the app on more than server.

> Load Balancer > Cluster > worker thread

> XSS (Cross-Site Scripting):
	- attacker injects malicious JS code into your page, and the browser executes it.
	- steal cookies via JS access.
	- solution: http only cookies and helmet().

> CSRF (Cross-Site Request Forgery):
	- malicious website makes user sent request to its websites without knowing.
	- cookies will sent by default.
	- solution: CSRF token, sameSite cookies and Preflight Request.

> SQL and No SQL Injection:
	- inject native DB code.
	- may get, update or delete data.
	- solutions: ORM, ODM.

> SQL (Structured Query Language):
- relational DB, tables and rows, fixed schema.
- weak entity: entity that is depend on another strong entity which if is removed, this weak entity will be removed also, It has partial key.

- Data Definition Language (DDL): define or modify the database schema or structure, [create, alter, drop, truncate, rename].
- Data Manipulation Language (DML): manage data, [insert, update, delete].
- Data Query Language (DQL): fetch data, [select].
- Data Control Language (DCL): Commands that deal with user permissions and ensuring database security, [grant, envoke, deny].
- Transaction Control Language (TCL): Commands used to manage transactions, [commit, rollback].

- Drop: remove the table itself from DB.
- Truncate: remove all records from the table but keep the table structure.
- Delete: remove specific rows based on condition.
- Truncate is used to empty large tables as it is faster than delete. 

- Cross join, Inner join, left outer join, right outer join, full outer join.

- Function: Used to return a calculated value and can be used inside SELECT.
- Stored Procedure: Used to execute a set of SQL statements logic, better for performance.
- View: virtual table created from a SELECT query, security.
- Trigger: Automatically executes in response to database events.
